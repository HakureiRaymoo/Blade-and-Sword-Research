# 数据表结构

`bdh\<lang>\*.txt` 是 **GBK 编码、制表符分隔**的纯文本表格，首行是中文表头，之后每行一条记录。四种语言各一套，列结构一致、内容不同。这意味着**游戏的核心数值是"可直接编辑的文本"**，改 mod 不需要动二进制。

| 文件 | 行数（chs） | 列数 | 作用 |
| --- | --- | --- | --- |
| `PropMdl.txt` | 244 | 18 | 物品/道具 |
| `Role.txt` | 250 | 47 | 角色与动作参数（含战斗手感的全部入口） |
| `RoleQuest.txt` | 59 | 5 | 怪物图鉴 |
| `TriggerQuest.txt` | 99 | 6 | 章节/任务触发 |
| `Text.txt` | 384 | 2 | UI 字符串表（`id → 文本`） |
| `Dialog_Public1..3.txt` | 138+… | 3 | 公共对话（`ID / Dialog / 备注`） |
| `Dialog_private.txt` | 40 | 5 | 称谓表（按主角性别与身份变化） |

## 物品表 PropMdl.txt

```
道具名  ID  类型  地面图片ID  落地声音  界面图片ID  重迭  价值  等级  代号  功能
特别数据1  特别数据2  特别数据3  特别数据4  事件  道具说明文字  月份
```

样例（原文以制表符分隔，这里用 `·` 表示制表符，空列保留）：

```
小血瓶·4·10·6·43·6·0·40·1·HP1·Atb HP 400········HP1·小血瓶：恢复微量生命
血瓶··5·10·9·43·9·0·130·3·HP2·Atb HP 1350·······HP2·血瓶：恢复少量生命
```

几个可直接利用的点：

- **`功能` 列是一门小型表达式语言**：`Atb HP 400` / `Atb HP 25%*Atb MP 25%`，即"对属性 HP 施加 400"与"百分比对"两种写法，`*` 表示同时生效。这是药品、宝石、buff 的统一效果 DSL。
- `特别数据1..4` 与 `事件` 列是扩展点（任务道具、触发器挂接）。
- `地面图片ID` / `界面图片ID` 直接索引 `zy/*.Lib` 的条目号 —— **改图标 = 改这两个数字**。

## 角色表 Role.txt —— 战斗系统的入口

47 列，前 5 列是身份（`角色名称 / 角色ID / 手动ID / 头像ID / 图形ID`），其余是动作偏移与手感参数。

> **校正（2026-11-07）**：
> - `图形ID` 是 `SprRole` 的**角色编号**，不是 `zy/*.Lib` 的条目下标
> - 动作列的值是 **512 帧时间轴上的偏移**（帧号 = 时间步×8 + 朝向），不是条目号
> - 全 47 列的画像（类型/取值范围/是否为空）见 [../docs/04-role-columns.md](../docs/04-role-columns.md)

| 分组 | 列 | 含义 |
| --- | --- | --- |
| 姿态 | `平休1` `战休1` `平时走路` `战斗走路` `跑步` `初始态` | 各状态在时间轴上的起始偏移 |
| 受击 | `挨打` `硬直` `浮空` `起身` `死亡` | 受击反馈与硬直时长 |
| 防御 | `防守` `防守块*盲目块` | 格挡与破防 |
| 序列 | `自由序列` `先后序列` `预读动画` | `预读动画` 是 18 个动作偏移；`自由序列`/`先后序列` 存的是**身体部位代码**（`LA`/`RA`/`TK`/`HD`…，与 `SprRole.h` 同一套），且**只有怪物有值** —— 驱动攻击时的肢体顺序 |
| 表现 | `光影效果` `R*G*B` `死亡块` `大小` `脚数` `方向与头` | 渲染与朝向 |
| AI | `平时思想` `攻击思想` `性格1/3/4` `组` | 行为参数。其中 `平时思想`/`攻击思想`/`性格3`/`性格4` **全表为空（未启用）**；`组` = 初始阵营（`10001` 玩家方 / `3` 敌对 / `101` 友好） |
| 声音 | `平时声音` `战斗声音` `挨打声音` `死亡声音` | 索引 `sy/*.sy` |
| 招式 | `挨打返技` `死亡技` `移动技` `抗技能` | 特殊技 |

样例（剑客）：

```
剑客 | 4 |  | 33 | 901 |
001*001*005*000*000*000*000*005*001 | 001 | 16 | 16*0*272*224*464*159 |
48 | 48*32*64 | 80 | 0 |
16*32*48*64*80*96*112*128*144*176*192*208*240*256*288*304*320*336 |
112 | 96*144 | 352 | 128*4 | 384 | 400 | ...
```

数值用 `*` 分隔表示**多段/多帧列表**（如 `预读动画` 是 18 个帧号的序列），空表示未定义。这套"用文本表达帧序列"的做法，正是原版连招编辑器能存在的前提。

## 字符串与对话

- `Text.txt`：`id <TAB> 文本`，被 UI 引用；改它即可本地化界面文字而无需碰 exe。
- `Dialog_Public*.txt`：`ID <TAB> Dialog <TAB> 备注`，`////` 是对话框分段符，`%5%` 之类是角色名占位符（配合 `Dialog_private.txt` 的称谓表替换，例如"他/她"随主角性别变化）。
- `Dialog_private.txt`：`ID <TAB> 男主角 <TAB> 女主角 <TAB> 力士 <TAB> 老和尚 <TAB> 老英雄`，同一 ID 在五种身份下取不同称呼。

## 对现代化的意义

1. 这些表足以支撑一个**外部编辑器**：改数值、改文案、改图标索引，全部是文本操作，天然可 diff、可版本管理。
2. `Role.txt` 的"序列/硬直/浮空"列，是复刻战斗手感时最有价值的原始参数 —— 重制版应当先原样导入这套表，再在编辑器里可视化。
3. 四语言并置，说明本地化早已是数据驱动；重制版可以直接沿用这套 key。
