# 路线图

> 目标：在**不改动原始资产分发**的前提下，把《刀剑封魔录》与《上古传说》推进到"现代操作、现代显示、可编辑"的状态，并为最终的双作合一重制积累可验证的技术资料。

## 阶段划分

每个阶段都有**可验证的退出条件**，避免"感觉做完了"。

### M0 · 勘察（已完成）

- [x] 安装目录语义、体积构成
- [x] `leyiLib2.0` 容器规范（5 个库全部校验通过）
- [x] `.sy` = WAV、`.dhp` = MPEG-1、`.txt` = GBK 表、`.sav` 结构
- [x] 引擎身份（Leyi）、PE 结构、导入表、启动时序
- [ ] `.fol` 容器（阻塞在逆向，转入 M1）

**退出条件**：任一容器可以用自写代码遍历，且结构性问题（缺文件、长度不符）能被工具报出来。

### M1 · 资产管线（进行中）

- [x] `lep` 像素解码：RGB565 / 行内多段 / 无压缩
- [x] 用 `map_nanfang.lib` 的 6,300 张等长瓦片做验证（全部 64×32，行宽对称变化）
- [x] 批量导出：`.Lib` → PNG + `index.json`（`tools/rekit/export_assets.py`）
- [x] 精灵帧包拆分（`u32 count + u32 offsets + lep[]`）
- [x] 宽高语义定案：磁盘字段是构建期残留，引擎按行表修正（运行时 99.4% 吻合）`n- [ ] 帧锚点：已确认 **不在 `lep` 内**（图像对象无原点字段），转入动画层（`Role.txt` 序列 / `.fol`）
- [ ] `id → 名称` 映射表：从 `Role.txt` / `PropMdl.txt` 的 ID 列 + `SoundMdl.sy` 建立
- [ ] 音频/视频转码：`.sy` → OGG，`.dhp` → MP4（ffmpeg 一把梭）
- [ ] **重打包**：改图写回 `.Lib` 并保持索引连续
- [ ] `.fol` 定位（与逆向并行）

**退出条件**：`export_assets.py` 一次产出全量图集 + 音视频 + 索引 JSON，抽查 20 张图与游戏内画面一致。

### M2 · 数据管线

- [ ] 为 7 类表建立 schema（列名、类型、可选值）
- [ ] `txt` ↔ JSON 双向转换，**round-trip 字节级一致**（GBK、`\r\n`、制表符、空列全部保留）
- [ ] `功能` 列表达式 `Atb HP 25%*Atb MP 25%` 的解析与校验
- [ ] 存档读写：长度前缀字符串流 → 结构化对象

**退出条件**：改一个物品的攻击力 → 写回 → 游戏内生效；且不改动任何一行时，转换后的文件与原件逐字节相同。

### M3 · 运行时仪表化（为手感复刻取真值）

- [ ] 进程注入框架（DLL，可加载/卸载）
- [ ] 输入 hook：抓到鼠标坐标、按键、Alt 组合手势
- [ ] 战斗事件日志：当前招式 ID、帧号、命中判定、硬直/浮空时长
- [ ] 导出"手感数据集"：给定输入序列 → 实际动画与判定序列

**退出条件**：能录下"剑客 3 段连招"的完整帧级轨迹，并与 `Role.txt` 的序列列对上号。

### M4 · 可控改造（Track A 交付）

- [ ] 宽屏：逻辑分辨率与 HUD 锚点
- [ ] 帧率：解除 60 帧上限，逻辑与渲染分离
- [ ] 手柄：XInput 映射到鼠标手势（右摇杆画轨迹 / 径向轮盘）
- [ ] 外部连招编辑器：读写 `Role.txt` + 实时预览

**退出条件**：用手柄完整通关第一章，且连招编辑器改出的招式在游戏内可触发。

### M5 · 重制原型（Track B）

- [ ] Godot 4 工程骨架 + 资产导入器
- [ ] 单角色、单场景、完整招式链
- [ ] 输入缓冲与取消窗口对齐 M3 数据集

**退出条件**：原型中同一串输入产生的连段，与 M3 记录的帧轨迹在 ±1 帧内吻合。

### M6 · 双作合一

- [ ] 两部作品的数据表合并（同名 ID 冲突解决）
- [ ] 章节串联与存档迁移

## 依赖关系

```
M0 ──> M1 ──> M2
       │
       └──> M3 ──> M4
              └──> M5 ──> M6
```

M1 是唯一的硬前置：拿不到图，后面全是空谈。
M3 与 M1/M2 可并行（一个攻二进制，一个攻资源）。

## 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| `lep` 是硬件相关编码（如 16bit 565 + 抖动） | 导出的图有色差 | 先解 `map_*`（规整瓦片）验证，再解 UI，最后解角色 |
| 帧序列与动画绑定在代码里而非数据里 | 连招编辑器无法只靠文本 | M3 的运行时日志就是兜底 |
| 重制手感偏离 | 项目失去意义 | 以 M3 数据为准绳，逐帧对齐 |
| 版权与分发 | 法律风险 | 仓库只存代码与文档，资产由用户本地生成 |
