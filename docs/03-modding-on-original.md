## 1. 可改的面（按风险从低到高）

| 层 | 位置 | 需要重打包？ | 风险 | 能改什么 |
| --- | --- | --- | --- | --- |
| **A. 散装文本表** | `bdh/<lang>/*.txt` | ❌ 不用 | 极低 | 名称、物品、任务、对话、角色数值 |
| **B. `.fol` 里的表** | `mb.fol` → `Role.txt` / `Skill.ini` / `player/Init.txt` / `trigger/` | ✅ `fol.py pack` | 低 | 战斗数值、技能、初始属性、触发器 |
| **C. 图像** | `zy/*.Lib` 的 `lep` 条目 | ✅ `leylib.py pack` | 中 | 图标、立绘、地图、精灵 |
| **D. 场景** | `cj.fol` → `.MAP` / `.BNT` / `.ONT` / `.Scn` | ✅ `fol.py pack` | 中高 | 地图布局、刷怪、传送门 |
| **E. 程序行为** | `ComeOn.exe` 补丁 / 内存补丁 | — | 高 | 失焦继续跑、硬编码上限、UI 行为 |

**建议的推进顺序：A → B → C → E → D。**

A 和 B 就是"改数值"和"改手感"，投入产出比最高，而且完全可逆。

## 2. 工作流

```
1. 备份        —— 每个动过的文件旁边留一份 <name>.orig（table_edit.py 自动做）
2. 取副本      —— 解包到 out/ ，只在副本上改
3. 改          —— 文本用 table_edit.py；图像/场景用各自的工具
4. 打包        —— fol.py pack --from <原文件>（保留种子与目录里的其余字段）
5. 安装        —— 覆盖游戏目录里的同名文件
6. 验证        —— 进游戏看现象
7. 回滚        —— 把 .orig / 备份覆盖回去
```

`fol.py pack --from` 会**沿用原文件的种子与每条记录里除偏移/大小之外的字段**，
所以未改动的部分和原文件完全一致，改动面被压到最小。

## 4. 第一个实验：结论

**问题**：`Role.txt` 有两份（`bdh/chs/Role.txt` 散装、`mb.fol` 里打包），引擎读哪个？

**答案：读散装那份。** 把 `bdh/chs/Role.txt` 里剑客的 `平时速度` 从 `8` 改成 `14`，
进游戏立刻能感知到变化 —— 说明 `bdh/<lang>/` 就是权威数据源，
以后**改数值不需要重打包任何容器**，零风险。

### 顺带纠正一列的语义

改完之后的现象不是"走得更快"，而是**迈步变慢、行走动画被拉长**。
所以 `平时速度` 不是"速度"，而是**每一步的节拍长度**（值越大，一步占用的时间越长）。

真正想让人走快，应该**减小**这个值。于是第二步实验把 `8` 直接改成 `4`。

### 迭代不需要重启游戏

BugLog 里 `EndLoading` 之前有一串 `End <角色名> <角色ID>` 的计时行，
说明**角色数据是在进地图时加载的**。所以调数值的循环是：

```
改 bdh/chs/Role.txt  ->  过一道门 / 读一次档  ->  看现象
```

不必反复重启。
