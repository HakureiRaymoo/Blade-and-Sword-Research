# CE 端操作规程 / Cheat Engine capture kit

本目录放**由用户手动在 Cheat Engine 里执行**的 Lua 脚本。
我（agent）在低完整性沙箱里，只能通过 `ce_tcp_relay.py` 让 CE 做事、无法直接开进程；
而 CE 自己的 Lua 引擎是最省事、最不抢焦点的通道。

---

## 0. 现在先做这一步：把游戏重新打开

刚才为了验证 `noactivateapp=true` 强杀过一次游戏，`ddraw.ini` 已经**回滚**到原始内容
（30579 字节，`[comeon]` 段只剩 `maxgameticks=60` / `fixchilds=3`）。

请正常启动游戏（Steam 里点开始，或 `steam://rungameid/2924510`），
进到一张有主角的地图里站好。**不要**停在主菜单。

---

## 1. 粘脚本

1. 打开 Cheat Engine（它已经开着，并且有 `DaojianServer` 的窗口列表也行）。
2. 菜单 **Table → Show Cheat Table Lua Script**（快捷键 `Ctrl+Alt+L`）。
3. 打开 `tools\ce\capture_runtime.lua`，**全选、复制、整个粘进 Lua Engine**。
4. 点 **Execute**。

脚本会自动做两件事：

- 立刻抓一次快照（此时 CE 在前台，游戏可能已暂停，没关系，先看结构在不在）；
- 装一个**全局 F6 热键**，之后每按一次 F6 抓一次。

CE 的 Lua Engine 窗口**别关**（关了热键就没了），最小化可以。

> 脚本只扫可写内存（`+W`），但全内存 AOB 仍然会让 CE 卡几秒到几十秒，
> 期间窗口无响应是正常的，别强杀。

---

## 2. 然后按 F6（关键）

1. 点一下游戏窗口，让它回到前台。
2. 站在原地，按 **F6**（第 2 次快照）。
3. 走动两步 / 砍一刀，再按 **F6**（第 3 次快照）。

三次快照分别代表：**暂停态 / 待机态 / 动作态**，我拿它们互相 diff，
就能看出哪些结构是"当前动作"、哪些是"当前帧"。

抓完跟我说一声，文件在：

```
out\ce\snapshot_<日期>_<时间>_<序号>.txt
```

---

## 3. 如果 F6 按下去没反应

- 可能是 CE 的 Lua Engine 被关了 → 重新粘一次 Execute。
- 或者直接改用手动：在 Lua Engine 里再次点 **Execute**，就等于再抓一次。
  （脚本里 `capture()` 在入口就会跑一次。）

---

## 4. 万一想抓得更细

`capture_runtime.lua` 顶部的常量可以直接改：

| 常量 | 含义 |
| --- | --- |
| `MAX_IMG` | 最多记录多少个 `lep` 图像对象（默认 400） |
| `MAX_OBJ` | 最多记录多少个库条目对象（默认 600） |
| `PREVIEW` | 每个对象预览多少个双字（默认 24） |
| `PROT` | AOB 扫描的内存保护标记，`+W` = 只扫可写 |

---

## 为什么抓这三类东西

| 类别 | 依据 |
| --- | --- |
| `lep\0` 图像对象 | 之前已验证：运行时图像对象以 `lep` 头开始，`+0x15` 是 bpp，`+0x30` 是行表 |
| vtable `0x005540A4` 等 | 反编译 `FUN_005050c0` 得到：`*param_1 = &PTR_FUN_005540A4`，即条目对象的第一个双字就是 vtable |
| `+0x1C/+0x24/+0x28/+0x2C` | 反编译 `FUN_005051e0` / `FUN_005050f0` 得到：类型、数据指针、子对象表、子对象数量 |

目的是把**磁盘上的 `Spr` 描述表**和**内存里的运行时对象**对上，
从而确定"一帧里到底画哪几层、每层偏移多少"——这是目前唯一还缺的一环。
